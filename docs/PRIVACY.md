# Privacy: what Loreweaver does with data

This document says what data the product handles, where it goes, how long it stays, which settings limit it, and how a world's data is deleted. It describes what the code and the configuration do today. It is not legal advice, and where a statement about a provider rests on that provider's public documentation, the source is named so it can be checked again: provider terms change.

## 1. In short

- **The product stores very little.** Its database holds the lore passages and their vectors, a log of requests (ids and counts, no text) and a log of thumbs clicks (ids, no text). It stores no conversations, no accounts and no names.
- **What an author types and the lore that answers it leave the product.** Each question goes to the model provider with the passages and the character state that answer it, and to the embedding provider as a vector query. When tracing is on, the same content is also written to a tracing service.
- **Two providers cannot be pinned to the EU:** the model provider (inference may run anywhere, or be pinned to the US) and the embedding provider (its region is not stated). Everything the project controls is in the EU.
- **There is no "delete my data" action yet.** Deleting a world's data is a set of steps, in section 7, with one gap: the thumbs log and the traces are not labeled with a world.

## 2. Data the product handles

| Data                                | Example                                               | Comes from                            | Personal data?                                                                                   |
| ----------------------------------- | ----------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Lore**                            | A rule of magic, a place, a character's backstory     | Markdown files, written by the author | Not about real people unless the author writes it so. It is the author's unpublished work        |
| **Character state**                 | Location, mana, health, inventory of a character      | The story service                     | Not about real people (fiction)                                                                  |
| **Questions and answers**           | "How can Aria escape?", the answer with its citations | The author, and the model             | Can contain anything the author types, including a pasted scene                                  |
| **A visitor id**                    | A random id in a cookie                               | Created by the server                 | Yes, in the legal sense: an identifier that singles out a browser. It carries no name or contact |
| **A world choice**                  | `world_aethel`                                        | A cookie set by the server            | No                                                                                               |
| **Thumbs and copy clicks**          | "up", on message `m1` of chat `c1`                    | The author's click                    | Chat and message ids only; no text and no visitor id                                             |
| **IP address and request metadata** | The address a request came from                       | The network                           | Yes. Seen by the hosting providers in their logs; not stored by the product                      |

The product's own scope says it never stores or searches a manuscript: a pasted scene is used for that answer and kept by none of the product's tables. It is not private from the providers below, which receive it.

## 3. Where the data goes

```text
Browser ──► Hosting (Vercel, functions in Paris) ──┬─► Model provider (Anthropic)       questions, passages, character state, drafts
                                                   ├─► Embedding provider (Voyage AI)   the question, as text to embed
                                                   ├─► Database (Supabase, eu-west-1)   lore passages and vectors, request log, thumbs log
                                                   ├─► Story service (Cloud Run, europe-west1)   character state
                                                   └─► Tracing (LangSmith, EU region)   inputs and outputs of each run, when tracing is on
Developer's machine ──► the same providers, with development keys
CI (GitHub Actions) ──► Anthropic and Voyage, with a CI key; the lore of the seed worlds and test questions only; tracing off
```

| Hop                           | What is sent                                                                                                                  | Why                                 | Region                                                                                             |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------- |
| Browser to the app            | The whole conversation (the browser keeps it, there is no server-side history), the world cookie, the visitor cookie          | To answer and to apply limits       | The function region is Paris (`cdg1`)                                                              |
| App to the model provider     | The system prompt, the conversation, the tool results (passages of the lore and the character state), and the drafts to check | To write and to check the answer    | Inference runs in "global" geography by default; it can be pinned to the US. There is no EU option |
| App to the embedding provider | The author's question (and, at indexing time, the lore passages)                                                              | To search the lore by meaning       | Not stated in the provider's FAQ                                                                   |
| App to the database           | Passages, vectors, request and click rows                                                                                     | Search, limits and cost             | EU (`eu-west-1`)                                                                                   |
| App to the story service      | A character id                                                                                                                | To read the character's state       | EU (`europe-west1`)                                                                                |
| App to the tracing service    | Each run's inputs and outputs: the question, the passages, the character state, the draft and the answer                      | To see inside a run and to price it | EU region of the provider                                                                          |

A trace of a run contains the same text the model provider receives, so tracing is a second copy of an author's content. It is off unless `LANGSMITH_TRACING` is set; in CI it is off.

## 5. What the product stores, and for how long

| Where                        | What                                                                                                                            | Kept                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `lore_chunks` (database)     | The text of each lore passage, its vector, its world, file and heading                                                          | Until the lore is changed and indexed again, or the rows are deleted. It is an index: the files are the source |
| `usage_events` (database)    | One row per chat request: the visitor id, the world, the model and prompt version, token counts, cost, latency, status. No text | **No expiry is set.** Rows stay until deleted                                                                  |
| `feedback_events` (database) | One row per click: chat id, message id, kind, model, prompt version. No text, no visitor id, no world                           | **No expiry is set.** Rows stay until deleted                                                                  |
| Cookie `lw_world`            | The world the visitor chose                                                                                                     | One year; HttpOnly, SameSite=Lax, Secure when deployed                                                         |
| Cookie `lw_visitor`          | A random id, used for the rate limit and the daily budget                                                                       | One year; HttpOnly, SameSite=Lax, Secure when deployed                                                         |
| The browser                  | The conversation on screen                                                                                                      | Until the page is closed or reloaded                                                                           |
| Traces (tracing service)     | Inputs and outputs of each run, labeled with the environment, the model and the prompt version                                  | 14 days, longer in the cases listed in section 4                                                               |
| Logs (hosting, cloud)        | Request metadata, including the address of the caller                                                                           | As each provider's plan allows                                                                                 |

The two cookies are used only to run the product: to know which world to answer about and to stop one browser from spending without bound. Neither is used for advertising or tracking across sites. There is no cookie banner.

## 6. GDPR notes

- **Roles.** Loreweaver's operator decides why and how the data is processed, so it is the controller of the visitor id, the request log and the click log. The providers in section 4 process data on its behalf (processors or sub-processors).
- **Lawful basis.** For the request log and the visitor id: a legitimate interest in running the service and preventing abuse (the rate limit and the budget). For the content of questions and lore: the author's own use of the service. When accounts exist, performance of the contract with the author becomes the basis for the account's data.
- **Minimization.** The product stores no conversation text, no names and no contact details. Rows hold ids and counts. The visitor id is random and carries nothing about the person.
- **Retention.** The periods are in section 5. Two logs have no expiry yet; a periodic deletion of old rows is an open item.
- **Rights of the data subject (access, correction, erasure, objection, portability).** Without accounts the product cannot tie a request to a person: the only handle is the visitor id in an HttpOnly cookie that the person cannot read. A request is handled by finding the rows from what the person can supply, and by section 7. A self-service action is not built.
- **Sub-processors.** The list is the table in section 4. Anthropic and Voyage AI may process data outside the EU, so transfers to them need the transfer mechanism of their data processing terms (standard contractual clauses or the equivalent); the terms in force are **to confirm** before real authors use the product.
- **Information to visitors.** The page tells visitors that suggestions are AI-generated. It does not yet link to a privacy notice; that notice is an open item.

## 7. Deleting a world's data

A world's data is in four places that are deleted in different ways. Replace `<world_id>` with the id (for example `world_aethel`) and run the statements against the database in `DATABASE_URL` (the Supabase pooled string for the hosted one).

| Data                        | How it is deleted                                                                                                                                                                                                 | Gap                                                                                                                                    |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Vectors and passages**    | `DELETE FROM lore_chunks WHERE world_id = '<world_id>';` Then remove the world's folder from `data/lore/` so that a later `pnpm ingest` does not index it again                                                   | None. This removes every chunking configuration of the world                                                                           |
| **Request rows**            | `DELETE FROM usage_events WHERE world_id = '<world_id>';`                                                                                                                                                         | None. The rows hold no text                                                                                                            |
| **Thumbs and copy rows**    | A row has a chat id and a message id but no world, so it cannot be selected by world. Delete by chat id if it is known: `DELETE FROM feedback_events WHERE chat_id = '<chat_id>';`                                | **Not deletable by world.** The rows hold no text and no visitor id, so they say nothing about a world's content                       |
| **Traces**                  | Delete the traces through the tracing service's API or its interface, or delete the whole project (`loreweaver-dev` or `loreweaver-prod`). Traces expire by themselves after 14 days unless they were kept longer | **Traces are not labeled with the world.** Finding one world's traces means searching their content, or deleting by time or by project |
| **Copies at the providers** | Anthropic deletes within 30 days by default. Voyage keeps nothing, since the organization opted out. Nothing in the product can delete these on request                                                           | Cannot be forced from here; the periods are in section 4                                                                               |
| **Character data**          | The story service owns it. For a hosted deployment it is a file inside a container that is reset when a new container starts                                                                                      | Not part of Loreweaver's own storage                                                                                                   |

Two improvements would close the gaps: carrying the world id in the click rows and in the trace labels, and a script that runs these deletions. Neither is built.

## 8. Region choices

The project chose the EU for everything it controls: the database (`eu-west-1`), the story service (`europe-west1`), the function region (Paris) and the tracing workspace (EU). Two choices are outside its control: the model provider offers only a global or a US-only inference setting, and the embedding provider does not state a region. The first is why a question about an author's world can be processed outside the EU, which is the main privacy cost of using these models.

## 9. Related points

- **The EU AI Act.** The product is most likely a limited-risk system: a chatbot for creative help that does not decide anything about a person. The duty that applies is transparency: people must be able to tell they are talking to an AI, which the page does with a permanent "AI-generated suggestions" label and a note under the text box. The Act's duty to mark AI-generated content in a machine-readable form is not implemented for the text of the answers. Commentary read in October 2026 says the duties of this kind have applied since 2 August 2026, with a later date for systems already on the market for the marking duty; the exact text should be checked before relying on that.
- **Copyright and ownership.** The lore and any pasted scene are the author's. The product does not train on them. The providers' terms say what they may do with the data (section 4). The answers are suggestions, and what the author uses of them is the author's responsibility.
- **Security of what is stored.** The tables have Row Level Security on with no policy, the keys are in environment variables and secrets and never in the code, and each environment has its own keys (a development key and a production key for the model and tracing providers, and a separate key for CI).
